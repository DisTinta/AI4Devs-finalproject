# The last Entrega 2 tickets run as an autonomous Workflow, with four human gates relaxed

## Status
Accepted

## Context and problem
On 2026-10-16, six days before the Entrega 2 deadline (2026-10-22), twelve leaf tickets of CODEMIND —
Entrega 2 were still open: DIS-76, DIS-78, DIS-21, DIS-26, DIS-34, DIS-44, DIS-45, DIS-58, DIS-60,
DIS-65, DIS-66 and DIS-101. Every ticket so far ran with the author in the loop, through the full SDD
cycle (`/enrich-us` → `/opsx:propose` → `spec-auditor` → `/opsx:apply` in TDD → three reviews →
`/opsx:archive` → merge). The author asked whether an agent could run the rest unattended, resolving
open questions as a lead engineer would, and report only the resolved tickets at the end. The session
that framed the experiment is recorded in
[`docs/ai-sessions/04-experimento-workflow-autonomo-entrega-2.md`](../ai-sessions/04-experimento-workflow-autonomo-entrega-2.md).

Four rules block an unattended run: `docs/base-standards.md` §88 (the human approves any plan touching
more than three files), §90 (tests are authored or supervised by a human), §99 (merges are signed by a
human), and the author's rule that the "why" of ADRs and PRs is written by the author. DIS-34 (review of the
golden answers) was also defined as non-delegable, because an AI validating answers generated by
another AI weakens the evaluation reference.

## Options considered
* **Keep the manual flow**: one ticket at a time with the author in every gate.
* **`/loop` in one long session**: unattended, but the context saturates after a few tickets, and
  `/usage` showed that 81 % of the week's usage already came from contexts above 150k tokens.
* **A Claude Code Workflow**: a script that runs the tickets in dependency order and spawns a fresh
  subagent per step, with Opus on judgement steps and Sonnet on mechanical ones, and a pilot of two
  tickets before the rest.

## Decision
We choose **the Workflow, with a pilot on DIS-76 and DIS-78 first**, because:
* The SDD cycle stays intact: the same skills, agents, hooks and three reviews run on every ticket;
  only who signs the gates changes.
* Fresh subagents keep each step's context small, which is where the week's usage was going.
* The pilot measures the real token cost against the manual tickets before committing the rest.
* It is an explicit experiment of the master's subject (agentic delivery), documented with its cost
  and its failures in `readme.md` (DIS-101, criterion E).

For this run only, the author relaxed the gates as follows:
* §88: `spec-auditor` plus a lead-engineer subagent approve the plan; every decision it takes is
  written, in Spanish, in the ticket's Enhanced description in Linear.
* §90: tests are written by `tdd-test-writer` from the spec scenarios, without human supervision.
* §99: the agent merges, only after the `/opsx:archive` commit and with CI green.
* The agent writes the "why" of ADRs and PRs, marked as the agent's decision.
* DIS-34 becomes hybrid: the agent reviews every golden (`reviewed_by: agent:claude-opus-5-5`), and
  the author signs a sample (every `UNKNOWN`, every golden the agent flags as doubtful, and two or
  three at random) before the ticket is closed.

## Consequences
* The author reviews the agent's decisions after the fact, not before; a wrong decision may already be
  merged and need a follow-up change.
* The golden set keeps a human anchor only through the sample; its independence is weaker than a full
  human review, and `readme.md` states it.
* Every rule above returns to its normal form after this run; this record does not change
  `docs/base-standards.md`.
* A run stopped by CI, a merge conflict, Ollama or the usage limit leaves the ticket in In Review with
  a Linear comment, and the remaining independent tickets continue.
