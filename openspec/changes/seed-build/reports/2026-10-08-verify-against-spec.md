## 2. Requirements missing or partial

No requirement is missing. Partly proven:

- "`npm run seed:build` SHALL take no arguments": extra arguments are ignored, not rejected; no test. The spec should say which reading holds.
- "the connection SHALL always be closed": the code closes it (`defaultOpenTransaction` → `end()` in `release`), but tests only assert the fake `base.release`.

Scenario tests weaker than their scenario:

- Integration "The acme-shop seed is generated": does not check `created_at`/`indexed_at` against the `HEAD` commit date; table order checked through first appearances only.
- Integration "Two consecutive builds…": the "no id equals a database id" query runs after the savepoint rollback, so it only sees the two unrelated projects (the unit render scenario is what proves it).
- Integration "An existing acme-shop project does not block the build": the existing project has no rows, and only its `file` count is checked.
- Unit "Ids derive from natural keys…": "shuffled" is a reverse; the id-equals-key check covers a sample of rows.
- Unit "A fingerprint changes with content, files or parser versions": the `web-tree-sitter` case adds an input instead of changing a version (the version change is checked in an extra assertion and in the lockfile extra case).

## 3. Unspecified behaviour

1. **Every edge key gets an occurrence suffix, `#0` when unique.** The spec ("Edges that share the whole key … SHALL get an occurrence index") and design D4 add it only to duplicates. The committed seed follows the code. Anything recomputing ids from the spec text (DIS-92, CM-HU-14.1) would get other edge ids. Either amend the spec or change the code and regenerate the 170 edge ids. **Pending author decision.**
2. A fourth header line, "Generated by `npm run seed:build`; do not edit by hand." (design D5, not the spec).
3. Empty tables are omitted with their blank-line separator.
4. Test seams `exportRows` and `buildHistory(fixturesRoot, repoRoot)` not listed in design D1.
5. Fingerprint edge cases: non-regular files skipped; content read as UTF-8; a lone CR is not normalised (only CRLF).
6. Fingerprints are computed before the history rebuild (design D1, not the spec); a lockfile without a parser dependency fails as `INTERNAL`, untested end to end.
7. `missingConfig` in `seed-build.ts` duplicates the one in `compose-index.ts`.

Changes to `fixtures/build-history.mjs`, `package.json`, `vitest.config.ts` and the adapter's index export are declared in the proposal or design. No undeclared dependency; no extra output field.
