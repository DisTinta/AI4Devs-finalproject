## Why

The L1 store can persist commits and file–commit links (DIS-23), but nothing reads them from a
repository: `GitPort` and `@codemind/adapter-git` are empty stubs. Indexing (DIS-85) and co-change
edges (DIS-36) are blocked on a history extractor that the domain can call, and that — per readme
§2.5 — never lets a contributor's name or e-mail reach the store. This is DIS-35 (CM-HU-03.1), a
slice of CM-HU-03 (DIS-25).

## What Changes

- **`GitPort` contract** in `packages/core/src/ports/GitPort.ts` (replaces the stub):
  `readHistory(repoPath)` → `GitHistory { head?, commits, fileCommits }`, reusing `GraphCommit` and
  `GraphFileCommit`.
- **Pure privacy and parsing rules in core** (`packages/core/src/knowledge/`), unit-tested and under
  Stryker:
  - `pseudonymiseAuthor(identity, salt)` — keyed hash (HMAC-SHA256) of the normalised author e-mail;
  - `extractPrNumber(message)` — `(#N)` in the subject or `Merge pull request #N`;
  - `stripIdentityTrailers(message)` — drops the seven identity trailers (`Co-authored-by:`,
    `Signed-off-by:`, `Reviewed-by:`, `Acked-by:`, `Reported-by:`, `Tested-by:`, `Suggested-by:`),
    which carry names and e-mails.
- **Domain error** `NotAGitRepository` in `packages/core/src/knowledge/errors.ts`.
- **`simple-git` adapter** in `packages/adapters/git/src/`: `createSimpleGitHistory({ authorHashSalt })`
  implementing `GitPort` with a single `git log --numstat` pass, and `authorHashSaltFromEnv(env)` that
  fails loudly when `AUTHOR_HASH_SALT` is missing or blank.
- **New dependency** `simple-git` in `@codemind/adapter-git` (already chosen in readme §2.2).
- **`.env.example`** gains `AUTHOR_HASH_SALT=` (empty, commented; never versioned with a value).
- Tests: unit tests for the core rules; integration tests against temporary repositories and
  `fixtures/acme-shop` regenerated by `fixtures/build-history.mjs`, including the DoD: the 32 acme-shop
  commits persisted through `StorePort.saveGraph` with no author name or e-mail in any row. The
  `git-history` spec has 20 scenarios (17 at first apply, 3 added after verify-against-spec), each mapped 1:1 to a test of the same name.

## Non-goals

- No `co_changed` edges and no `weight` formula: DIS-36 (CM-HU-03.2).
- No indexing use case: combining analyzer + git + store, reading `process.env` in the CLI and
  dropping links to paths absent from the snapshot are DIS-85 (CM-HU-05a.2).
- No rename tracking (`--follow`, `-M`): history is read with `--no-renames`.
- No remote PR or issue lookup (GitHub API): the PR number comes only from the message.
- No per-person analysis or "who knows what" (discarded in readme §2.5).
- No `npm run seed:build` (CM-HU-06), no HTTP route, no CLI command, no migration, no change to
  `StorePort` or `store-postgres`.
- The salt is never committed: fixtures have fictitious authors and seeds will carry precomputed
  hashes (PH-11).

## Privacy and logging impact

The change handles personal data: Git author names and e-mails, including those inside commit
trailers.

- Raw identities exist only in memory while one `git log` output is parsed and are discarded after
  hashing; `GitHistory` never carries them.
- `message` is stored without identity trailers. Privacy expansion beyond the ticket's trailer list:
  besides `Co-authored-by`, `Signed-off-by`, `Reviewed-by`, `Acked-by` and `Reported-by` (DIS-35),
  `Tested-by` and `Suggested-by` are also removed, because they carry a name and e-mail in the same
  form; each of the seven has its own test.
- No logging in the adapter; error messages never include an identity or the salt.
- Without a salt the adapter refuses to start: there is no unsalted fallback.

## Capabilities

### New Capabilities

- `git-history`: the `GitPort` contract — reading a repository's commit history with pseudonymised
  authors, sanitised messages, PR numbers and per-file line counts, and its failure modes.

### Modified Capabilities

(none — `graph-store` already persists commits and file–commit links; this change produces them)
