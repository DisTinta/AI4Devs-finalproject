## Why

DIS-71 delivered the core `drift` use case (functionality F6 of the parent story DIS-48, CM-HU-20):
it finds the statements of a project's documents that the code contradicts, with verified citations
on both sides. Nobody can use it yet: there is no command that runs it, it answers `UNKNOWN`
`llm-required` in evaluation mode (the mode an evaluator without a model key runs), and it writes no
`query_log` row, so the daily spend ceiling (`withDailyBudget`) never sees what a live run costs. This
is DIS-73 (CM-HU-20.2), the second half of CM-HU-20; its DoD is that `npm run cli -- drift acme-shop`
in evaluation mode prints the golden report. Its blockers DIS-71 and DIS-26 are done.

## What Changes

- **New CLI command `codemind drift <project> [--doc <path>]`** (`packages/cli/src/commands/drift.ts`),
  built like `ask`: it resolves the project by exact name, runs the core `drift` once with a new
  verification cache, wraps a live model in `withDailyBudget` when `DAILY_BUDGET_USD` is set, prints
  the report as text (one section per document, each contradiction typed `[INFERENCE]` with its
  statement, its claim, the document citation and the code citations with their verification and
  excerpts of up to 5 lines), prints `UNKNOWN (<reason>)` for an unknown report, writes the events to
  stderr as JSON lines and exits `0`/`1`/`2` like `ask`.
- **Golden drift report in the core `drift`**: before the evaluation-mode branch, in both modes,
  `drift` looks the key `drift:` (or `drift:<docPath>`) up in the project's answer cache; a valid
  stored drift report is answered as it is, with `cacheHit: true`, zero usage and no model call. This
  reopens decision D8 of DIS-71, as its Follow-up R8 allowed. A run with the model never writes the
  cache. `DriftRequest` gains `useCache?`; an answered report gains `cacheHit`.
- **`query_log` row with `capability = 'drift'`**, written by the core `drift` for every returned
  report (golden, live, or unknown with zero counters) and for a rejection after at least one model
  call resolved, so the daily ceiling sees the spend of a live run.
- **Versioned golden drift report `seeds/drift/acme-shop.json`** (demo question Q5 of acme-shop),
  generated by a new command `npm run drift:build` with a live model (local Ollama), in its own file
  format with a `driftFingerprint`, loaded by `npm run db:seed` into the answer cache under the key
  `drift:`, and checked by a coherence test.
- **Docs**: `readme.md` (`drift` is delivered, no longer planned), `docs/project-context.md`,
  `fixtures/README.md` (Q5 row and the golden paragraph), `docs/DEMO.md` (a `drift acme-shop` step in
  evaluation mode, captured by the agent in PowerShell 7 and Windows PowerShell 5.1).

Out of scope (non-goals): case B of `fixtures/README.md` (an implemented and tested rule that no
document mentions); an HTTP endpoint, a web screen, a `--json` output and proposed corrections to
the document; saving the reports of live runs in the answer cache, and storing contradictions as
claims (D7 of DIS-71 stands); checking the golden drift report in `npm run verify` (DIS-44 covers
`explain` golden answers only); a blind panel review of the golden drift report (it ships with
`reviews: []`); any change to `npm run cache:build` and to the golden `explain` answers.

## Capabilities

### New Capabilities

- `cli-drift`: the `drift` command of the CLI: its arguments, configuration and connection, project
  resolution, the text of a report and of an `UNKNOWN`, its events, failures and terminal safety, and
  the golden report served in evaluation mode over the loaded seed.
- `drift-golden`: the versioned golden drift report of the sample projects: the `npm run drift:build`
  command that produces it with a live model, its file format, its fingerprint, its atomic write and
  the coherence of the versioned file.

### Modified Capabilities

- `drift-detection`: the request accepts `useCache`; the golden drift report is looked up in the
  answer cache before the evaluation-mode check and served with `cacheHit: true`; the report carries
  `cacheHit`; `drift` writes one `query_log` row per returned report and one per rejection after a
  resolved model call (and records the hit of a golden entry) instead of writing nothing.
- `seed-load`: `npm run db:seed` also checks the golden drift files of `seeds/drift/` before
  connecting and saves their reports as answer cache entries in the same transaction; the idempotent
  load replaces them by key.

## Impact

- **Code**: new `packages/cli/src/commands/drift.ts`, `packages/cli/src/drift-build.ts`,
  `packages/cli/src/cache/drift-golden-file.ts`, `packages/cli/src/cache/build-support.ts` (helpers
  moved out of `cache-build.ts`, no behaviour change; the unsafe-content check takes the list of
  secrets instead of the private `Plan`); new `packages/core/src/drift/drift-cache.ts` and
  `packages/core/src/drift/query-log.ts`; changed `packages/core/src/drift/{drift.ts,drift-request.ts,
  drift-report.ts,index.ts}`, `packages/cli/src/index.ts` (dispatch and help),
  `packages/cli/src/seed-load.ts`, `packages/cli/src/cache-build.ts` (imports the moved helpers),
  `package.json` (script `drift:build`). No `explain`, `context`, `verify` or `knowledge` file is
  edited, so neither the golden-answer fingerprint nor the seed fingerprints change.
- **Data**: new `seeds/drift/acme-shop.json`. No migration: `query_capability` holds `drift` since
  migration 0002, and the golden report is an ordinary `cache_entry` row whose key (`drift:…`) never
  equals an `explain` key, which holds no `:`.
- **Contract**: `@codemind/core` gains `driftCacheKey`, `storedDriftReportSchema`,
  `parseStoredDriftReport`, `driftQueryLogEntry`, `saveDriftRow`, `useCache` in `DriftRequest`,
  `cacheHit` in `AnsweredDrift` and the `query_not_logged` member of `DriftEvent`. No HTTP route.
- **Cost and privacy**: a live run is bounded by the DIS-71 limits and is now visible to
  `withDailyBudget`; the document text and the model output reach stdout only as escaped excerpts
  and statements, never an error line or a log line; the versioned golden is refused if it holds the
  planted AWS key shape, the absolute path of the repository or of the build workspace, the value of
  `DATABASE_URL` or `LLM_BASE_URL`, or the API key.
- **Process**: the coherence test of the golden drift report checks its fingerprints in the unit
  suite, which amends a consequence of ADR `20261017-stale-fingerprint-fails-verify`; a new ADR records
  it (design D8, D14).
- **Tests**: new unit and integration tests for the command, the cache lookup, the row, the golden
  file, the build and the coherence; existing tests that change are named in `tasks.md` step 9.
