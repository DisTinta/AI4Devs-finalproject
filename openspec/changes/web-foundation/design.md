## Goals / Non-Goals

**Goals:**

- One place per concern that DIS-60, DIS-65 and DIS-66 extend without rework: the `routes` table, the
  `@theme` tokens, the API client and its two error classes, and an a11y gate that scans whatever the
  routes render.
- Every new tool works on Windows (author) and on the Ubuntu runner with Node 20.

**Non-Goals (design level, besides the proposal's):**

- No shared layout route: the wireframe 2 header (back arrow, project name, counters) differs from the
  wireframe 1 header, so each screen composes its own header; this change only provides `AppHeader` for
  the placeholders and the not-found screen, which DIS-60 may reuse.
- No runtime validation of the API bodies (no Zod in the browser), no retry inside the client, no
  React Query or global state.
- No component library, no icon set, no dark mode.

## Decisions

Decisions D1–D16 come from the DIS-58 `[enhanced]` description (agent as lead engineer, ADR
`20261016-autonomous-workflow-run-entrega-2`); D17–D25 were taken while proposing and are recorded in
the same description.

### D1 — An OpenSpec change with the new capability `web-foundation`

The original ticket called OpenSpec optional ("only if the author wants a spec of the router"). The
client's behaviour (which failure is `ApiError` and which `ApiUnavailableError`, the health-check time
limit, cancellation) is consumed by three tickets, and the a11y gate and the contrast are verifiable
requirements; without a spec DIS-60/65/66 would infer them from code. The spec scenarios are the
acceptance criteria of the ticket.

### D2 — `react-router` 7 in data mode; routes `/`, `/p/:projectId`, `*`

`react-router ^7` (7.18.x on 2026-10-17: peers `react >=18`, engines `node >=20`). Version 8 needs React
19 and Node 22. `router.tsx` exports the `routes: RouteObject[]` table and `createAppRouter()` (=
`createBrowserRouter(routes)`); tests and the a11y gate mount the same table with
`createMemoryRouter(routes, { initialEntries })` + `RouterProvider`. Routes:

| Path | Element | Until |
|---|---|---|
| `/` | `PendingScreen` with heading «Elige un proyecto para explorar» (the wireframe 1 heading) | DIS-60 |
| `/p/:projectId` | `PendingScreen` with heading «Consulta del proyecto» and the `projectId` | DIS-65 |
| `*` | `NotFoundPage` | — |

No `/p/:projectId/impact`: no impact API nor Screen 3 in Entrega 2; a route without a destination is
dead code. The wireframe 2 address bar shows `localhost:5173/acme-shop`; the parent's AC `/p/{id}`
wins (the id is what the API takes). Alternatives rejected: local state with `useState` (no deep link to
`/p/{id}`, no browser history); TanStack Router (a second router model for three routes).

### D3 — Tailwind 4 through `@tailwindcss/vite`, configured in CSS

`tailwindcss ^4` and `@tailwindcss/vite ^4` (4.3.x; the plugin's peer is `vite ^5.2 || ^6 || ^7 || ^8`).
`index.css` = `@import "tailwindcss";` + one `@theme { … }` block. No `tailwind.config.js` and no
PostCSS config (frontend-standards §1: configuration in CSS). Alternatives rejected: Tailwind 3 (JS
config, contrary to the standard); CSS modules or plain CSS (the standard names Tailwind).

### D5 — Font, sizes and radii

`--font-sans: 'Segoe UI', system-ui, sans-serif` (overrides Tailwind's default `font-sans`, applied on
`body` in `index.css`'s `@layer base`, together with `bg-canvas text-ink`). The SVG sizes (9–20 px) live on a
720 px canvas; in the browser they map to Tailwind's scale and no text goes under 12 px (`text-xs`).
Radii: `--radius-card: 8px`, `--radius-button: 4px`; badges use `rounded-full`. The footer annotation
«PANTALLA 1 — …» of the wireframe is not UI.

### D6 — Test tools

Root `devDependencies` (where Vitest lives): `jsdom ^26` (27 needs Node ≥ 20.19, the project allows
20.11), `@testing-library/react ^16` + `@testing-library/dom ^10` (mandatory peer), `@testing-library/user-event
^14` (interaction as a person does it, frontend-standards §4), `axe-core ^4`. No `@testing-library/jest-dom`:
`getByRole` already throws when the element is missing. Vitest stays on 1.6.

### D7 — Where tests live; the `test:a11y` script

Component, router, client and theme tests next to the code in `packages/web/src/**/*.test.ts(x)`
(type-checked by the web `tsconfig.json`, which already includes `src`). The a11y gate in `tests/a11y/`
(the path of frontend-standards §4 and `frontend.yml`) with its own `tests/a11y/tsconfig.json`
(extends `packages/web/tsconfig.json`, `include: ["**/*.tsx", "**/*.ts"]`), added to the root
`typecheck` script, because `tests/tsconfig.json` compiles neither `.tsx` nor DOM. Root script
`"test:a11y": "vitest run tests/a11y"`. The full suite runs `tests/a11y` too; running it twice in
`frontend.yml` costs seconds and is accepted.

### D8 — Same origin through the Vite proxy

The client calls relative URLs (`/health`, `/api/...`). `vite.config.ts` declares one `apiProxy` table
`{ '/api': 'http://127.0.0.1:3000', '/health': 'http://127.0.0.1:3000' }` and uses it for
`server.proxy` and `preview.proxy` (`127.0.0.1`, not `localhost`, to avoid resolving `::1` while the API
listens on IPv4). No `VITE_API_URL`: evidence is local only (closed decision 1); changing the API's
`PORT` means changing the proxy, written in one line of `docs/project-context.md`. Alternatives rejected:
CORS in the API (a change to `packages/api`, a non-goal); an absolute base URL from an env variable
(shipped to the browser, and cross-origin needs CORS anyway).

### D9 — The client's error model

Two classes in `services/api-client.ts`, both extending `Error`:

- `ApiError { status, code, message, details }`: the response status is ≥ 400 and the body is a JSON
  object with `error.code` (string), `error.message` (string) and `error.details` (a non-null,
  non-array object). Anything else at ≥ 400 is not the API speaking.
- `ApiUnavailableError { cause }`: `fetch` rejected (other than the caller's abort), the body is not
  JSON, a `200` body is not a non-null object, a ≥ 400 body is not in the error format, or the health
  time limit expired.

`getHealth({ signal?, timeoutMs = 5000 })` and `ask(projectId, body, { signal? })`. `ask` has no default
time limit: with a local model on CPU an answer takes tens of seconds. The client never retries (retry is
a UI action, DIS-60). No Zod in the browser: the API already serialises through its schemas
(`api-foundation`); the client only checks the JSON shape that decides between success and the two
errors. Status `2xx` other than `200` is treated as success (the API only answers `200` on these routes).

### D10 — Types declared once, guarded by a type-level contract test

`HealthResponse`, `AskRequest`, `AskResponse` (= `AskAnswered | AskUnknown` written out),
`ApiErrorBody` are written by hand in `services/api-client.ts` (frontend-standards §3). The contract
test `tests/unit/web/api-contract.spec.ts` uses `expectTypeOf<Client>().toEqualTypeOf<Api>()` for each
pair against `AskBody`, `AskResponse`, `ErrorBody` and `z.infer<typeof healthResponseSchema>`; `tsc -p
tests/tsconfig.json` (inside `npm run typecheck`) fails on any drift. A negative control under
`// @ts-expect-error` (the client ask body with `question` renamed) proves the comparison rejects a drift.
Rejected: importing `@codemind/api` from the web (pulls Fastify, Zod and core into the web's type graph
and risks the bundle); generating types from OpenAPI (a new dependency and build step for four types).
Only `health` and `ask`: no impact API, no invented types.

### D11 — The a11y gate scans the real routes

`tests/a11y/smoke.a11y.test.tsx` renders `routes` in a memory router at `/`, `/p/<acme-shop id>` (taken
from `SAMPLE_PROJECTS[0].id`, not copied) and `/ruta-que-no-existe`, and runs axe (D21). When DIS-60/65
replace the placeholders, the gate scans the real screens without editing the test. The negative control
(an `<img>` without `alt`) proves axe runs. axe in jsdom does not compute styles, so it cannot judge
colour contrast (it reports it as incomplete, not as a violation): that is D12's job.

### D12 — Contrast test over the tokens

`packages/web/src/theme.test.ts` reads `index.css` as text (D24), extracts every `--color-<name>: #rrggbb`
declared in `@theme`, and for each pair of D4's table (written in the test as token names) checks the
token resolves to the spec's value and the WCAG ratio is ≥ 4.5. The ratio helper is a small pure function
in `packages/web/src/theme-contrast.ts` (relative luminance + ratio), also checked against known values
(`#4dabf7` on white → 2.48, failing; black on white → 21).

### D13 — Standards and documentation

`docs/frontend-standards.md`: the Tailwind and RTL + jsdom *target* notes go; §4 "Wiring `test:a11y`"
becomes "How `test:a11y` is wired" (file, script, surfaces it scans, negative control, what axe in jsdom
cannot check). The Playwright note stays in both standards: Playwright is not installed here (DIS-75).
`docs/TESTING.md` (Accessibility row), `docs/DEPLOYMENT.md` (`Frontend` row) and
`docs/project-context.md` (Commands: `test:a11y`, the web `dev` proxy; Testing: jsdom environment,
cleanup, where web tests live) are updated.

### D14 — Every dependency is justified

| Dependency | Where | Why | Alternative rejected |
|---|---|---|---|
| `react-router ^7` | web `dependencies` | three routes with a parameter and deep link `/p/{id}` need a real URL and history | `useState` routing (no deep link); v8 (React 19, Node 22) |
| `tailwindcss ^4` | web `devDependencies` | the styling system named by frontend-standards §1, configured in CSS | Tailwind 3 (JS config) |
| `@tailwindcss/vite ^4` | web `devDependencies` | Tailwind 4's Vite integration, no PostCSS config | `@tailwindcss/postcss` (one more config file) |
| `jsdom ^26` | root `devDependencies` | DOM for component and a11y tests; axe and RTL are proven on it | `happy-dom` (axe-core support is partial); jsdom 27+ (Node ≥ 20.19 / 22) |
| `@testing-library/react ^16` | root | render + accessible queries (frontend-standards §3–4) | Enzyme (unmaintained) |
| `@testing-library/dom ^10` | root | required peer of RTL 16 | — |
| `@testing-library/user-event ^14` | root | full interaction sequences (pointer, keyboard) | `fireEvent` (dispatches one event, not what a person does) |
| `axe-core ^4` | root | the a11y engine the standard and the scaffold name | `vitest-axe`/`jest-axe` wrappers (an extra layer over the same engine) |

Tailwind goes to the web's `devDependencies` because it only runs at build time; `react-router` ships to
the browser.

### D15 — Bounded visual evidence

`/show-spec-working` starts `npm run dev`, captures `/` and an unknown path and compares them with
`images/pantalla-1-seleccion.svg` only for what this change sets: dark header with «CODEMIND» and the
tagline, font, page background and white container, link colour. The cards are DIS-60's. It also sends
`GET http://localhost:5173/health` through the proxy with the API up and down. Screenshots go next to the
report.

### D16 — Texts in Spanish

The UI is in Spanish (`index.html` `lang="es"`, wireframes): «Elige un proyecto para explorar»,
«Consulta del proyecto», «Esta pantalla está en construcción.», «Página no encontrada», «Volver a la
selección de proyecto», the tagline. Code, tests and repository docs stay in English.

### D17 — jsdom only for `.test.tsx` of the web and for `tests/a11y` (refines D6)

`vitest.config.ts` → `environmentMatchGlobs: [['packages/web/**/*.test.tsx', 'jsdom'], ['tests/a11y/**',
'jsdom']]`. The `[enhanced]` text said `packages/web/**`; it is narrowed because `.test.ts` files of the
web (client, theme) need no DOM, and under jsdom the global `AbortSignal` is jsdom's while `fetch` stays
Node's, and Node's `fetch` rejects a foreign signal. Keeping them in Node avoids that mismatch and keeps
them fast. Alternative rejected: `// @vitest-environment jsdom` comments per file (easy to forget in
DIS-60/65/66).

### D18 — DOM cleanup through one guarded setup file

RTL only cleans up automatically when the test framework exposes a global `afterEach` (Vitest
`globals`, off here). `tests/support/dom-cleanup.ts` is added to `test.setupFiles`: it registers
`afterEach` that, only when `document` exists, dynamically imports `@testing-library/react` and calls
`cleanup()`. Node tests pay one `typeof` check. Alternatives rejected: `globals: true` (changes every
existing test's environment); `afterEach(cleanup)` in every component file (DIS-60/65/66 would have to
remember it, and a forgotten one leaks DOM between tests).

### D19 — The contract test imports by relative path (refines D10)

The `[enhanced]` text proposed adding `@codemind/api` to `tests/tsconfig.json` `paths`. The existing API
unit tests import the API by relative path (`../../../packages/api/src/...`); the contract test follows
that convention with `import type` from `packages/api/src/schemas/{ask,common}` and
`packages/web/src/services/api-client`, so neither `paths` nor a Vitest alias changes. `api-client.ts`
only uses globals that both the DOM lib and `@types/node` declare (`fetch`, `Response`, `AbortSignal`,
`AbortController`, `setTimeout`), so it type-checks in both projects.

### D20 — Time limit with `AbortController` + `setTimeout`

`getHealth` creates its own `AbortController`, aborts it from a `setTimeout(timeoutMs)` (cleared in
`finally`) and from the caller's signal (listener removed in `finally`), and passes its signal to
`fetch`. A rejection after the timer fired becomes `ApiUnavailableError` (cause: a `TimeoutError`
`DOMException`); after the caller aborted, the caller's `signal.reason` is rethrown. Rejected:
`AbortSignal.timeout` + `AbortSignal.any` (Vitest fake timers do not drive `AbortSignal.timeout`, so the
5 000 ms scenario could only be tested in real time).

### D21 — axe runs over the whole document with `lang` and `title`

The gate sets `document.documentElement.lang = 'es'` and `document.title = 'CODEMIND'` (as
`index.html`) before rendering and runs `axe.run(document)`, so page-level rules (`html-has-lang`,
`document-title`, `landmark-one-main`, `page-has-heading-one`, `region`) apply too. The kit scaffold ran
axe on the container only. Each scan awaits the routed screen (`findByRole('heading', { level: 1 })`)
before axe runs.

### D22 — The proxy table is tested as configuration

`tests/unit/web/vite-config.spec.ts` (Node) imports `packages/web/vite.config.ts` and asserts that
`server.proxy` and `preview.proxy` both map `/api` and `/health` to `http://127.0.0.1:3000`. The live
behaviour (through the proxy with the API up and down) is checked in the manual interface test.

### D23 — JSX transform declared in the Vitest config

The root Vitest config has no React plugin; esbuild would take `jsx` from the nearest `tsconfig.json`.
`vitest.config.ts` sets `esbuild: { jsx: 'automatic' }` explicitly so `.tsx` tests compile with the React
17+ runtime whatever tsconfig is found. Rejected: adding `@vitejs/plugin-react` to the root config
(Fast Refresh is useless in tests).

### D24 — The theme test reads `index.css` with `?raw`

`import css from './index.css?raw'` (typed by `/// <reference types="vite/client" />` in
`src/vite-env.d.ts`) keeps the web sources free of `node:fs`. If Vitest 1.6 does not return the raw text
for a CSS `?raw` import, the fallback is `readFileSync(new URL('./index.css', import.meta.url))`, recorded
in the task.

### D25 — Stryker skips the web tests

`vitest.stryker.config.ts` adds `packages/web/**`, `tests/a11y/**` and `tests/unit/web/**` to its
`exclude`: Stryker mutates no web file, so those tests can kill no mutant and would only slow its dry run
and load jsdom into it.

## Risks / Trade-offs

- [Tailwind 4's native engine (`@tailwindcss/oxide`) needs a prebuilt binary per platform] → the lock
  file is regenerated with `npm install` on Windows; `npm ci` on Linux installs the optional Linux
  binary because npm records every platform's optional package in the lock file. The CI `Frontend` job
  proves it (`typecheck` + build-free tests do not load Tailwind; `npm run build -w packages/web` is run
  in the test task to prove the build on both systems).
- [`environmentMatchGlobs` is deprecated in later Vitest majors (replaced by `projects`)] → accepted on
  Vitest 1.6; the upgrade ticket replaces it.
- [axe in jsdom misses contrast and focus visibility] → D12 covers contrast; keyboard and focus are
  checked by hand in `/show-spec-working` (frontend-standards §3).
- [The proxy hides a stopped API as an empty `500`] → that is exactly why such a body is
  `ApiUnavailableError` (D9) and has its own scenario.
- [The full suite now also renders React in jsdom] → a few seconds more in `quality`; Stryker excludes
  them (D25).
- [`ask` without a time limit can wait forever on a hung API] → the caller's signal cancels it; DIS-65
  owns the UI that offers cancelling.

## Migration Plan

Additive except `App.tsx` (removed; nothing imports it besides `main.tsx`). Rollback = revert the PR;
no data, no API change. After merging, run `npm install` (new dependencies).
