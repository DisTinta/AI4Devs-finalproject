## 10c. Panel

This group is done by independent agents launched outside the apply: panelist 1 (Opus) and panelist 2 (Sonnet), blind to each other and to every earlier round; then the recording step; then a resolver (Opus, fresh context). Every rule below is fixed before any judgement and the criterion is the DIS-33 criterion, copied verbatim. Where the description of any Linear ticket differs from this group, this group prevails.

**Input set.** The seven items of `docs/golden-review/panel/2026-10-golden-review-dis-9-input.json`, in order: task-api `Q1`, `Q2`, `Q3` (golden), task-api `Q4` (behaviour item, `kind: "unknown"`, answer `UNKNOWN (no-anchor)`, no statements), acme-shop `Q1`, `Q3`, `Q4` (golden). For a golden item you get the question, the `answer` text, each statement (`n`, `text`, `type` `FACT` or `INFERENCE`, and `evidence`: the numbers of the evidence entries it cites) and each evidence entry (`n`, `path` relative to the fixture root `fixtures/<project>/`, `startLine`, `endLine`). The input has no excerpt: open the cited lines in the fixture yourself.

**Criterion** (judge against the fixture code at this commit; the golden answers are in Spanish):

- Judge each statement as one of: `true` — true against the code and backed by the lines of the evidence it cites; `false` — contradicted by the code; `unverifiable` — a cited evidence entry does not exist (file or lines) or its lines do not back the statement, even if the statement is true elsewhere; `overtyped` — typed `FACT` but the code does not state it literally (true only by inference). A statement typed `INFERENCE` that the code states literally is `true` (under-typing is not an error).
- An **error** is any statement judgement other than `true`.
- Judge the item's `answer` text: `"true"` if what it says is true against the code, `"false"` otherwise. For the behaviour item task-api `Q4` («¿Cómo se autentican los usuarios?»): `"true"` if the fixture has no authentication (no route, middleware, hook, plugin or check that authenticates a user), so `UNKNOWN` is the due answer; `"false"` if it has any.
- **Verdict**, derived from the judgements, never chosen apart from them: `incorrect` if `answer` is `"false"`, or a `FACT` statement is judged `false`, or the item has statements and every one has an error; otherwise `correct` if every statement is `true` (the behaviour item, with no statements, is `correct` when its `answer` is `"true"`); otherwise `partial`.
- Spelling slips or typos of the model (for example a misspelt word) are noted in `notes` but are not errors. A statement that is true against the code but imprecise (for example it lists a route twice) is judged `true` and the imprecision is noted in `notes`.
- When more than one judgement applies to a statement, use the first that applies in this order: `false`, `unverifiable`, `overtyped`, `true`.

**Output format.** One JSON object per panelist, two-space indent, LF, final newline:
`{ "panelist": <1|2>, "model": "<your exact model id as your own system states it; expected claude-opus-5-5 for panelist 1 and claude-sonnet-5-5 for panelist 2; if yours differs, write yours>", "date": "YYYY-MM-DD", "sourcesRead": ["<repository-relative path of one file>", ...], "items": [ { "project": "task-api", "id": "Q1", "answer": "true" | "false", "verdict": "correct" | "partial" | "incorrect", "statements": [ { "n": 1, "judgement": "true" | "false" | "unverifiable" | "overtyped", "cites": ["fixtures/task-api/src/<file>.ts:<line>", ...] } ], "notes": "<one to three sentences in English, citing at least one fixtures/<project>/<path>:<line>>" } ] }`, with the seven items in input order and one judgement per input statement, in order (the behaviour item has `"statements": []`). A citation is `fixtures/<project>/<path>:<line>`, matched by `/fixtures\/(task-api|acme-shop)\/([A-Za-z0-9_.\/-]+):([0-9]+)/g` in a `cites` entry, a `notes` or a `justification`; it is valid when the project is the item's, the file exists in that fixture and the line is between 1 and the file's number of lines (a final LF is not a line). Ranges are not citations: cite a single line (a range `:a-b` is read as its first line `a`). Every statement (in `cites`) and every `notes` must carry at least one valid citation; other citations are ignored. For an `unverifiable` statement whose cited file or lines do not exist, cite the fixture line that shows the code the statement is about, or line 1 of the cited file if the file exists. Each `sourcesRead` entry names one file, never a directory (an entry ending in `/` or naming an existing directory), a glob, a path with a `..` segment, nor a Linear reference (no Linear source is allowed in this round). Every object has exactly the keys shown here: any other key, or a missing one, rejects the output. The resolution is `{ "resolver": "<your exact model id>", "date": "YYYY-MM-DD", "sourcesRead": [...], "items": [ { "project", "id", "verdict", "justification": "<one to three sentences>", "cites": ["fixtures/<project>/<path>:<line>", ...] } ] }`, with no `panelist` and no `model` field, holding only the items whose two verdicts differ, in input order (`"items": []` when there is none); each resolution item carries at least one valid citation in `cites` or `justification`.
