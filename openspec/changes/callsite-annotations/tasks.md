## 4. Panel

This group is done by independent agents launched by the workflow, outside the apply: panelist 1 (Opus) and panelist 2 (Sonnet), blind to each other; then the recording agent; then a resolver (Opus, fresh context). The apply does not do these tasks. Every rule below is fixed before any judgement (design D2, D4, D6, D8). Where the description of DIS-80 differs from this group (criterion, allowed sources, site fields, output format), this group prevails.

**Input set.** The 100 sites of `docs/measurements/annotation/acme-shop.sites.json` (50, PHP, ids `php-01`…`php-50`) and `docs/measurements/annotation/task-api.sites.json` (50, TypeScript, ids `ts-01`…`ts-50`). Each site gives `site.file` and `site.line` (relative to the fixture root: `fixtures/acme-shop/` or `fixtures/task-api/`), `form` (`call`, `new`, `read` or `reference`), `call` (for `call` / `new`, the call text up to and including its opening parenthesis, starting at the member operator `->m(` / `.m(` when the receiver of a chained call is on an earlier line; for `read`, the receiver and property name of a property read; for `reference`, the reference passed as an argument: an identifier or property access, a PHP array callable or a route action string) and `source` (the innermost enclosing named function or method, or the file for a call outside any; anonymous functions, closures and arrow functions are transparent). `control` only says whether the site is also used to measure agreement with a reference you may not read; judge every site the same way.

**Criterion** (the resolution a static analyzer *should* give when it reads only the fixture's own source files: no `vendor/`, no `node_modules/`, no standard-library or package declarations):

- `exact` — the target is fixed by declarations inside the fixture: a declared or inferred type of the receiver declared in the fixture, an explicit import or `use`, an explicit class name (`X::m()`, `new X(...)`, `[X::class, 'm']`), or a reference to a declared function or method.
- `heuristic` — the target is reached only by applying a known framework convention to fixture code: a Laravel facade (through its accessor and the container binding), a binding by string in the container, `__call` / `__callStatic`, an Eloquent attribute or relation read through `__get` (target: the declared accessor or relation method), a route action written as a string (`'Controller@method'`), `dispatch(new Job)` → the job's `handle`, `event(new E)` → the `handle` of the listener registered for `E` in `EventServiceProvider::$listen`.
- `none` — the target is outside the fixture's code (PHP or framework functions, `vendor`, `node_modules`, the standard library, Zod, Fastify), or it is only reachable through a receiver whose type is declared outside the fixture (a package or the standard library) and no convention of the `heuristic` list applies, or it cannot be determined statically.
- `expected` is `none` exactly when `target` is `null`.
- When a call names a method that is not declared and is served by a magic method, `target` is the symbol that exists in the code (the `__call`, the accessor). When a call can reach several symbols, `target` is the one declared first in the code and the reason names the others.
- A `form: reference` site is judged as the call the reference stands for: the target is the function or method it names.
- Precedence: the `heuristic` list wins over `none` when one of its conventions applies to fixture code (for example `event(new E)` or a job dispatch), even if the outer call is a framework function.
- `X::dispatch(...)` (also `dispatchSync`, `dispatchIf`, `dispatchUnless`, `dispatchAfterResponse`) on a fixture class that uses `Dispatchable` and declares `handle` → `heuristic`, target `X::handle`; `dispatch(new X(...))` likewise.
- `new X(...)` where `X` declares no constructor (neither itself nor a fixture parent) → `none`: no symbol exists to target.
- A method inherited from a fixture class → the symbol of the class that declares it (`Parent::m`).
- "Declared first", when a call can reach several symbols: first in the registration list when there is one (the `$listen` array, a container binding), otherwise by file path, then line.
- A `form: read` site is judged as the access `__get` serves: a declared accessor (`get{Studly}Attribute`) or relation method → `heuristic` with that target; a plain column with no declared accessor or relation → `none`.
- Symbol names: `Class::method` for methods (constructors `Class::__construct` in PHP, `Class::constructor` in TypeScript), a function by its name; `target.file` is relative to the fixture root.

**Output format.** One JSON object per agent, two-space indent:
`{ "panelist": <1|2>, "model": "<model id>", "date": "YYYY-MM-DD", "sourcesRead": ["<repository-relative path of one file, or 'linear:DIS-80/description'>", ...], "sites": [ { "id": "php-01", "target": { "file": "app/...", "symbol": "Class::method" } | null, "expected": "exact" | "heuristic" | "none", "reason": "<one or two sentences citing at least one file:line, path relative to the fixture root, e.g. app/<Dir>/<File>.php:<line> or src/<dir>/<file>.ts:<line>>" }, ... ] }`, with the 100 sites in id order. At least one citation of each reason must name an existing file of the site's fixture with a line between 1 and that file's last line; other citations are ignored. Each `sourcesRead` entry names one file (never a directory or a glob such as `fixtures/acme-shop/app/**`); entries are checked as path strings; the last segment of `target.symbol` (after `::`) must appear in `target.file`. The resolution is `{ "resolver": "<model id>", "date": "YYYY-MM-DD", "sourcesRead": [...], "sites": [...] }`, with no `panelist` and no `model` field, and its `sites` hold only the disagreement ids, each answer in the same shape.

**Allowed sources (allowlist).** Panelists: `fixtures/acme-shop/app/**`, `fixtures/acme-shop/routes/**`, `fixtures/acme-shop/config/**`, `fixtures/acme-shop/database/**`, `fixtures/acme-shop/composer.json`, `fixtures/task-api/src/**`, `fixtures/task-api/package.json`, `fixtures/task-api/tsconfig.json`, the two `*.sites.json`, this `tasks.md`, `docs/base-standards.md` and the **description** of Linear DIS-80 (`get_issue`, never its comments). **Agreement measure** (design D6). Per language, n = 50: agreed site = same `expected` and same `target` (`file` and `symbol`); percent agreement = agreed / n × 100; Cohen's kappa over `expected` (categories `exact`, `heuristic`, `none`), `null` when the expected agreement is 1. Per panelist and language, the same against the control sites (n = 12 / 10), kappa marked indicative.
