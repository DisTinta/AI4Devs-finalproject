## Why

Table 2 of the README (§2.6, graph quality by analyzer) needs a reference of 50 annotated call sites
per language, and `measure-graph` (Linear DIS-79, CM-HU-22.1) depends on it. `fixtures/README.md`
§ "Table 2 seed" has only a first batch (12 PHP + 10 TypeScript sites); 38 + 40 are pending. On
2026-10-27 the author changed the procedure: the reference is no longer human work but the output of
**two independent annotator agents of different models**, blind to each other, with a tie-break by a
third agent and a hash freeze before anything is measured. This change (Linear DIS-80, CM-HU-22.3,
parent DIS-53 / CM-HU-22) builds that reference so the coverage and precision DIS-79 computes are
measured against something nobody adjusted after seeing the results, and so the README can say
honestly how it was obtained.

## What Changes

- **Site lists (preparation).** `docs/measurements/annotation/acme-shop.sites.json` and
  `task-api.sites.json`: exactly 50 distinct call sites each, chosen from the fixtures' application
  code (PHP `app/**`, `routes/**`; TypeScript `src/**`). The first 12 / 10 are the control sites of
  `fixtures/README.md`, in its order (`php-01`…`php-12`, `ts-01`…`ts-10`, `control: true`); the
  rest cover the fixture's hard constructions (facade, container binding, `__call`, Eloquent magic
  attribute, string route action, job, event, imports, interface methods, `new`, method references
  and callbacks, re-exports, standard library, Zod, Fastify). A site carries where the call is and
  what it is, never an answer.
- **Control reference (preparation).** `docs/measurements/annotation/control.json` transcribes the
  22 README rows (target and expected resolution) before any panelist runs, so the control is fixed
  first; the README rows are not edited.
- **Agreement script.** `scripts/annotation-agreement.mjs` (+ `.d.mts`): pure functions and a small
  CLI that validate a panelist output, compute per language the percent agreement and Cohen's kappa
  between the two panelists and each panelist's agreement with the control, merge the final
  annotations deterministically and print SHA-256 hashes. It reads JSON files only: no graph, no
  database, no analyzer.
- **Panel (outside the apply).** Panelist 1 (Opus) and panelist 2 (Sonnet) annotate the same 100
  sites blind, from the fixture source code only, under a criterion written in `tasks.md` before any
  judgement; a third agent (Opus, fresh context) resolves only their disagreements. Raw outputs are
  kept in `docs/measurements/annotation/` so every figure can be recomputed.
- **Frozen annotations.** `fixtures/annotations/acme-shop.callsites.json` and
  `task-api.callsites.json`, format version 1 (the format DIS-79 consumes), generated by the script,
  never edited by hand.
- **Agreement report.** `docs/measurements/annotation-agreement.md`: method, models and date;
  per language n, percent agreement and kappa; control agreement per panelist (kappa marked as
  indicative); every disagreement with both answers and its resolution; the discrepancies with the
  control; the SHA-256 of every input, raw output and frozen file. A test fails if a recorded hash
  stops matching its file.
- **Docs.** `fixtures/README.md` § "Table 2 seed" points at the frozen files and the report instead
  of "pending" (the 22 rows unchanged); `README.md` §2.6 no longer says the sites are annotated "a
  mano" or by the author.

Out of scope (non-goals of DIS-80): the `measure-graph` script, any comparison with the `edge`
table and filling Table 2 (DIS-79); fixing the PHP or TypeScript analyzers when the annotations show
missing or extra edges; changing the 22 control rows of `fixtures/README.md` (design D9); Table 1
and the review of answers (DIS-81 and siblings); a hook that blocks edits to `fixtures/annotations/`
(design D11).
